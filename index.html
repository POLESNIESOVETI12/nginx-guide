3x-ui, Nginx и VLESS + REALITY

Один российский VPS на Ubuntu 24.04 и свой домен. На публичном 443 работает вход 3x-ui. Обычный браузер по тому же адресу откроет ваш сайт из Nginx.

1. Установить 3x-ui

Подключитесь по SSH к RU VPS. Запустите официальный установщик. Для панели выберите отдельный порт, например 2053. Вход на 443 создадим в шаге 3.

Дальше, когда: команда показала active. Сохраните адрес, путь, логин и пароль панели из вывода установщика. Если панель работает без TLS, открывайте её через SSH-туннель.

2. Настроить Nginx и свой сайт

Направить домен на RU VPS

В панели DNS добавьте A-запись с публичным IPv4 российского VPS. Для основного домена имя записи обычно @, для поддомена site.my-domain.example — site. Если уже есть запись AAAA, она должна вести на рабочий IPv6 этого же VPS.

Введите только имя, без https:// и пути. Для кириллицы используйте Punycode. Команды ниже подставят это имя автоматически.

Дальше, когда: команда показала публичный IPv4 вашего RU VPS.

Установить Nginx и добавить HTTP-конфигурацию

Nginx обслуживает публичный 80/TCP для сайта и проверки сертификата. Для HTTPS он будет слушать только 127.0.0.1:8443. Если эти адреса уже заняты, проверьте процессы перед настройкой.

Проверьте, что установка завершилась строкой active. Затем добавьте конфигурацию для my-domain.example. Команда создаёт отдельный файл для домена и проверяет синтаксис перед применением.

Дальше, когда: в выводе Nginx есть syntax is ok и test is successful. Сообщение Config already exists означает, что для этого домена уже есть конфигурация и её нужно проверить перед продолжением.

Поставить свою HTML-страницу

Вставьте свой HTML в поле или измените короткий пример. Нажмите «Копировать» под полем и вставьте весь блок в SSH. Он запишет /var/www/my-domain.example/index.html и сохранит прежний файл в /var/backups, если он был.

Дальше, когда: локальная проверка вернула HTTP 200, а страница открывается по http://my-domain.example/ с другого устройства. Если браузер сам меняет схему на HTTPS, проверьте HTTP в приватном окне или командой curl -I http://ВАШ-ДОМЕН/ с компьютера.

Выпустить сертификат и включить локальный HTTPS

Certbot проверит домен через Nginx на 80/TCP. При первом запуске он попросит почту и согласие с условиями. После выпуска добавьте отдельную HTTPS-конфигурацию на 127.0.0.1:8443.

Дальше, когда: локальный тест показал Nginx: HTTP 200. Публичный HTTPS проверим после создания входа.

3. Создать VLESS + REALITY на своём домене

В панели 3x-ui откройте «Входящие подключения» → «Добавить». Укажите параметры из таблицы. Поле SNI содержит только доменное имя. Поле «Цель» указывает на локальный Nginx.

Сгенерируйте ключи REALITY и Short ID. Добавьте клиента и сохраните вход. В экспортированном профиле в поле адреса используйте свой домен my-domain.example или публичный IP этого VPS. SNI в обоих случаях — my-domain.example.

Оставьте цель 127.0.0.1:8443. Цель с вашим доменом на :443 вернёт запрос на тот же вход Xray и может вызвать таймаут.

Готово, когда: Xray слушает 443, тест показывает Через Xray: HTTP 200, а сайт https://my-domain.example/ открывается с другого устройства без VPN. Затем отдельно проверьте подключение с экспортированным VLESS-профилем.

Если сайт не открывается
  • Открывается стандартная страница Nginx. Проверьте, что заходите по домену и что IP в шаге 1 совпадает с IP RU VPS.
  • Certbot не смог подтвердить домен. Сначала проверьте DNS и доступность HTTP снаружи. В сообщении Certbot ищите домен и причину отказа.
  • На 8443 есть ответ, а 443 зависает. Сверьте цель, SNI и Xver по таблице.
  • Ошибка address already in use. Команда ниже покажет, какие процессы слушают 80, 443 и 8443.

4. Закрыть лишние порты на RU VPS

Этот шаг выполняйте после проверки сайта и VLESS. Оставьте текущую SSH-сессию открытой. Сначала посмотрите, какой SSH-порт используется и какие правила UFW уже добавлены.

Для сайта, продления сертификата и VLESS в команду уже включены 80/TCP и 443/TCP. Локальный Nginx на 127.0.0.1:8443/TCP доступен Xray через loopback.

Дополнительные поля можно оставить пустыми. Если панель открываете через SSH-туннель, её порт в форме можно не указывать. Команда сверит SSH-порт с текущей сессией. Чтобы применить правила, введите латинскую y в запросе подтверждения. Любой другой ответ отменит запуск.

Короткая команда для стандартных портов

Используйте этот блок на RU VPS, если UFW уже установлен, текущая SSH-сессия использует 22/tcp и для ваших сервисов достаточно 80/tcp и 443/tcp. Сверьте SSH-порт командой выше. --force включает UFW без дополнительного запроса.

Если для прямого доступа к панели 3x-ui нужен отдельный порт или у вас есть другие входящие сервисы, укажите их в форме выше.

После включения: проверьте вход по SSH в новом окне, откройте сайт без VPN и выполните тест VLESS. Если в ufw status numbered остались лишние старые разрешения, удалите их по одному через sudo ufw delete НОМЕР, каждый раз пересматривая список. Запрет по умолчанию сохраняет уже существующие правила.
